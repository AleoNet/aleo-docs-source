# Standard Operations

These operations are available in `function`, `closure`, and `finalize` blocks — except for `async`, which is function-scope only.

## Arithmetic

| Opcode | Arity | Supported Types | Description |
|--------|-------|-----------------|-------------|
| `abs` | Unary | I8–I128 | Absolute value, halts on overflow |
| `abs.w` | Unary | I8–I128 | Absolute value, wrapping |
| `add` | Binary | Field, Group, I8–I128, U8–U128, Scalar | Addition, halts on overflow |
| `add.w` | Binary | I8–I128, U8–U128 | Addition, wrapping |
| `div` | Binary | Field, I8–I128, U8–U128 | Division, halts on overflow/zero |
| `div.w` | Binary | I8–I128, U8–U128 | Division, wrapping |
| `double` | Unary | Field, Group | Doubles the input |
| `inv` | Unary | Field | Multiplicative inverse, halts on zero |
| `mod` | Binary | U8–U128 | Modulo, halts on zero |
| `mul` | Binary | Field, Group×Scalar, Scalar×Group, I8–I128, U8–U128 | Multiplication, halts on overflow |
| `mul.w` | Binary | I8–I128, U8–U128 | Multiplication, wrapping |
| `neg` | Unary | Field, Group, I8–I128 | Negation, halts on overflow |
| `pow` | Binary | Field, (I8–I128)×(U8/U16/U32), (U8–U128)×(U8/U16/U32) | Exponentiation, halts on overflow |
| `pow.w` | Binary | (I8–I128)×(U8/U16/U32), (U8–U128)×(U8/U16/U32) | Exponentiation, wrapping |

| `sub.w` | Binary | I8–I128, U8–U128 | Subtraction, wrapping |

## Assert

| Opcode | Description |
|--------|-------------|
| `assert.eq` | Halts if operands are not equal |
| `assert.neq` | Halts if operands are equal |

Supported for all comparable types including Address, Boolean, Field, Group, integers, Scalar, Signature, Struct, and Record.

## Control Flow

| Opcode | Description |
|--------|-------------|
| `call` | Calls a closure or external function |
| `call.dynamic` | Dynamically calls a function by program/network/function fields *(V14)* |
| `async` | Produces a future for finalize execution (see [Futures](programs#futures)). Function-scope only. |
| `ternary` | Selects first or second value based on a boolean condition |

```aleo
call foo.aleo/bar r0 into r1;
ternary r0 r1 r2 into r3;   // if r0 then r1 else r2
```

## Cast

| Opcode | Description |
|--------|-------------|
| `cast` | Casts operands into the declared type |
| `cast.lossy` | Casts with lossy truncation for integer conversions |

`cast` supports conversion between all primitive types, and assembly of structs, records, and arrays from component values. Special destinations `group.x` and `group.y` extract coordinates from a group element.

## Serialization

*Added in Consensus V11.*

| Opcode | Description |
|--------|-------------|
| `serialize.bits` | Serializes a value to an array of booleans (Aleo variant encoding) |
| `serialize.bits.raw` | Serializes a value to an array of booleans (raw bit encoding) |
| `deserialize.bits` | Deserializes an array of booleans to a value (Aleo variant encoding) |
| `deserialize.bits.raw` | Deserializes an array of booleans to a value (raw bit encoding) |

## Dynamic Dispatch

*Added in Consensus V14 ([ARC-0009](https://vote.aleo.org/p/arc-0009)).*

Dynamic dispatch enables programs to invoke functions determined at runtime, unlocking interface patterns, pluggable libraries, and composable protocols.

### `call.dynamic`

Invokes a function whose target is resolved at runtime.

```aleo
call.dynamic <PROG> <NET> <FUN> with <INPUTS> (as <INPUT_TYPES>) into <OUTPUTS> (as <OUTPUT_TYPES>);
```

Identifiers can be written as quoted literals (`'credits'`, `'aleo'`, `'transfer_public'`), which are treated as field elements. A variable of type `field` is also accepted.

```aleo showLineNumbers
program token_router.aleo;

// Route a transfer to any compatible token program
function route_transfer:
    input r0 as field.public;          // token program name
    input r1 as address.public;        // recipient
    input r2 as u64.public;            // amount
    call.dynamic r0 'aleo' 'transfer' with r1 r2 (as address.public u64.public) into r3 (as future.dynamic);
    async route_transfer r3 into r4;
    output r4 as token_router.aleo/route_transfer.future;

finalize route_transfer:
    input r0 as future.dynamic;
    await r0;
```

**Allowed types:**

| Position | Allowed | Disallowed |
|----------|---------|------------|
| Inputs | Plaintext types, `record.dynamic` | `record`, external record, `future`, `future.dynamic` |
| Outputs | Plaintext types, `record.dynamic`, `future.dynamic` | `record`, external record, `future` |

**Restrictions:**

- `call.dynamic` can only appear in function bodies, not finalize blocks.
- The target program, network, and function are **public** circuit inputs. Do not use private data to select a call target — the target is observable.
- Dynamic targets cannot be resolved from onchain mappings at runtime. Callers supply targets as inputs (queried offchain), and finalize logic can verify them against stored values.

**Type translation:** when a `record.dynamic` is passed to a callee expecting a static record (or vice versa), the AVM automatically runs a translation circuit proving consistency between the two representations.

### Dynamic Record Access

| Opcode | Description |
|--------|-------------|
| `get.record.dynamic` | Retrieves a named field from a `record.dynamic` by verifying a Merkle proof that the entry exists with the specified type |

```aleo
get.record.dynamic r0.microcredits into r1 as u64;
get.record.dynamic r0.metadata into r2 as [u8; 32u32];
```

If the field does not exist or has an incompatible type, the Merkle proof fails and execution reverts. This enforces implicit record interfaces: any record containing the required fields satisfies the check, regardless of which program defined it.

The `owner` field is accessible directly without Merkle verification: `r0.owner`.
