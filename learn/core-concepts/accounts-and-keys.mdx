# Accounts & Keys

Every Aleo account consists of three cryptographic components: a **private key**, a **view key**, and an **address**. Each serves a distinct purpose, and together they enable Aleo's privacy model.

## Private Key

The private key is the root of an Aleo account. It's a randomly generated value from which the view key and address are derived.

- **Purpose**: Signs transactions and authorizes spending of records
- **Security**: Must be kept secret — anyone with the private key has full control of the account
- **Format**: Base58-encoded, 59 characters, prefixed with `APrivateKey1`:

```
APrivateKey1zkp8CZNn3yeCBJ6HoQCX7y4Rg5sFsfhJv1LKJaq9pGmWxG6
```

The private key is generated offline from a random 32-byte seed. No network interaction is required to create an account.

## View Key

The view key is derived from the private key and allows **read-only access** to an account's private records and transaction history.

- **Purpose**: Decrypts records and transaction data belonging to the account
- **Security**: Does not grant spending authority — safe to share for auditing purposes
- **Format**: Base58-encoded, 53 characters, prefixed with `AViewKey1`:

```
AViewKey1mSnpFFC8Mj4ABcQSD3q45xgaSJaKzPp1J4M7Uy5RM4ux
```

View keys are useful for compliance, auditing, and wallet recovery scenarios. A user can share their view key with an auditor to prove transaction history without giving up control of their funds.

:::tip
The account view key decrypts **all** records and transactions for the account. For more granular access, Aleo also provides **[record view keys](/learn/core-concepts/public-and-private-state#private-state-records)** (scoped to a single record) and **[transition view keys](/learn/core-concepts/transactions#transition-view-key)** (scoped to a single transition).
:::

## Address

The address is the public identifier for an account, derived from the view key.

- **Purpose**: Receives funds and identifies the account onchain
- **Security**: Public — safe to share freely
- **Format**: Bech32-encoded, 63 characters, prefixed with `aleo1`:

```
aleo1rhgdu77hgyqd3xjj8ucu3jj9r2krwz6mnzyd80gncr5fxcwlh5rsvzp9px
```

## Key Hierarchy

The three components form a one-way derivation chain:

```
Private Key → View Key → Address
```

You can derive the view key from the private key, and the address from the view key, but not the reverse. This means:

- Sharing your **address** reveals nothing about your view key or private key
- Sharing your **view key** allows read access but not spending
- Only the **private key** grants full control
