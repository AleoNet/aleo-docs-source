# Credits & Transfers

**Aleo Credits** are the native token of the Aleo network. They're used for transaction fees, staking, and transferring value. All credit operations are handled by the built-in `credits.aleo` program.

## Denominations

| Denomination | Value |
|---|---|
| 1 microcredit | Base unit |
| 1 millicredit | 1,000 microcredits |
| 1 credit | 1,000,000 microcredits |

All `credits.aleo` function parameters use **microcredits** as the unit.

## Holding Credits

Credits can be held in two forms simultaneously:

### Private 

Private credits are stored as encrypted **records**.  Each record contains an `owner` address and a `microcredits` balance, both encrypted.

- Your total private balance is the sum of all unspent credit records you own
- Spending a record consumes it and produces new records (payment + change)
- Your wallet must [scan the chain](../advanced/record-scanning.mdx) to identify which records belong to you and which have been spent

### Public

Public credits are stored in the `account` mapping — an onchain key-value store where the key is an address and the value is a microcredit balance.

- Your public balance is a single value, readable by anyone
- Similar to how balances work on Ethereum

You can hold credits in both forms at the same time and convert between them using the transfer functions below.

## Transfer Functions

`credits.aleo` provides five transfer functions, each with different privacy properties:

| Function | From | To | Privacy |
|---|---|---|---|
| `transfer_private` | Record | Record | Fully private — sender, receiver, and amount are all hidden |
| `transfer_public` | Mapping | Mapping | Fully public — sender, receiver, and amount are all visible |
| `transfer_private_to_public` | Record | Mapping | Sender is hidden, receiver and amount are public |
| `transfer_public_to_private` | Mapping | Record | Sender is public, receiver and amount are hidden |
| `transfer_public_as_signer` | Mapping (signer) | Mapping | Like `transfer_public`, but uses the original transaction signer as the sender |

### Private Transfers

`transfer_private` consumes a credit record from the sender and produces two new records: one for the recipient and one for the sender's change. No public information is revealed.

### Public Transfers

`transfer_public` updates the `account` mapping directly — deducting from the sender and adding to the receiver. Both addresses and the amount are visible onchain.

### Converting Between Private and Public

`transfer_private_to_public` and `transfer_public_to_private` allow users to move credits between the two forms. This is useful for:

- **Shielding**: Converting public credits to private records for privacy
- **Unshielding**: Converting private records to a public balance for use with programs that require public state

### Signer vs Caller

`transfer_public_as_signer` differs from `transfer_public` in one important way: it uses the **original transaction signer** as the "from" address, not the immediate function caller. This matters when a program calls `credits.aleo` on behalf of a user — `transfer_public` would use the intermediate program as the sender, while `transfer_public_as_signer` uses the actual user.

:::note
There is no `transfer_private_as_signer` function, as only the `owner` of a record is allowed to spend it.
:::

## Fee-Free Operations

Two special functions are exempt from base fees:

- **`split`** — Splits a private credit record into two records. Used for managing record sizes without incurring fees. 
    - **Note**: while `split` is exempt from base fees, a hardcoded 10,000 microcredit deduction is taken from one of the output records to prevent DoS attacks.
- **`upgrade`** — Upgrades a Version 0 record to Version 1 format (required to spend any records produced prior to Consensus V8 [^1]).

[^1]: This upgrade added the `sender_ciphertext` field to records.
